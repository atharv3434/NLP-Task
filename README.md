# Sentiment Analysis: Lexicon Baseline vs. Trained ML Model

A 3-class (positive / negative / neutral) sentiment analysis project that
trains and compares a classical **lexicon-based baseline** against a
**trained ML model** (TF-IDF + scikit-learn) — and, importantly, tests both
on a genuinely out-of-distribution hand-written set, not just data drawn
from the same templates as training. The honest result: both methods look
great on same-distribution data and both struggle on real generalization —
a useful, realistic finding rather than an inflated demo.

```
├── data/

├── src/
│   ├── utils.py                  # config + data loading
│   ├── lexicon_baseline.py       # classical rule-based sentiment scorer
│   ├── train.py                  # trains + evaluates ML models, saves the best

├── output/

│   └── comparison_report.md       # lexicon vs. ML, both test sets

```

## Setup

```bash
pip install -r requirements.txt
```

## 1. Train

```bash
python src/train.py
```

Trains **Multinomial Naive Bayes** and **Logistic Regression** (both on
TF-IDF features), evaluates on a held-out split of the templated data, and
saves whichever scores higher on macro F1 to `models/sentiment_model.joblib`.

On the templated test split, both models score **perfectly (1.000 accuracy)**
— expected, since the test data is drawn from the exact same small set of
sentence templates and vocabulary as the training data. This is the first
sign that a harder, more realistic test is needed (see step 2).

## 2. Evaluate — the real comparison

```bash
python src/evaluate.py
```

This is where it gets interesting. It compares the lexicon baseline and
the trained ML model on **two** test sets:

| Test set | Lexicon accuracy | ML accuracy |
|---|---|---|
| Templated (same distribution as training) | 0.933 | **1.000** |
| Hand-written, out-of-distribution | 0.333 | **0.433** |

The templated numbers look great for both methods. The hand-written set —
30 sentences I wrote directly, covering negation ("wasn't bad at all"),
sarcasm ("Oh great, another disappointing sequel"), and vocabulary never
seen in training ("riveting", "underwhelming", "lackluster") — tells a very
different story: **both methods perform barely better than chance (33%
baseline for 3 balanced classes).**

`output/comparison_report.md` includes specific disagreement examples,
e.g.:

> *"The movie wasn't bad at all, actually quite enjoyable."* — true:
> **positive**, lexicon: positive, ML: negative

Here the lexicon baseline's explicit negation-window logic gets it right,
while the ML model — trained on a template that says `"was not {adj} at
all"` — overfit to that surface pattern and misfires on the slightly
different real phrasing.

### Why this matters (and isn't a bug)

This is an honest and genuinely useful finding, not a flaw to hide: a model
trained only on a narrow set of synthetic templates learns the *shape* of
those templates, not general sentiment understanding. High accuracy on
data generated the same way as training tells you almost nothing about
real-world performance — you have to test on data that wasn't generated by
the same process you trained on. This is exactly the gap that real
sentiment datasets (larger, more diverse, human-written) are designed to
close, and it's the reason production sentiment models are trained on
things like millions of real reviews, not a few thousand templated
sentences.

## 3. Predict

```bash
python src/predict.py --text "This was a fantastic experience!" --compare-lexicon
```

```
Loaded model: Naive Bayes

[positive (0.86 confidence)]  This was a fantastic experience!
           lexicon baseline: positive
```

Also supports `--file <path>` (one text per line) and `--interactive` mode.
`--compare-lexicon` flags any case where the two methods disagree.

## How the lexicon baseline works

`src/lexicon_baseline.py` implements a small hand-crafted positive/negative
word lexicon plus basic negation handling: if a negation word ("not",
"never", "n't", etc.) appears within 3 tokens before a polarity word, that
word's contribution to the score is flipped. This is the same basic idea
behind tools like VADER (Hutto & Gilbert, 2014), just simplified — no
training data required, purely rule-based.

## Using your own data

1. Replace `data/reviews.csv` with your own labeled data (columns: `text`,
   `label`, with labels matching `config.yaml`'s `labels` list).
2. For a meaningful evaluation, also provide a genuinely held-out test set
   that wasn't generated the same way as your training data (real reviews,
   a different data source, etc.) — the whole point of `evaluate.py`'s
   two-test-set structure.
3. Re-run `python src/train.py` and `python src/evaluate.py`.

## Extending this project

- **Real training data**: swap in a real labeled sentiment dataset (e.g.
  movie or product reviews you have access to) in place of the synthetic
  templates — the pipeline code doesn't need to change.
- **Data augmentation**: paraphrase templates, vary sentence structure more,
  or mix in real text snippets to reduce the overfitting-to-templates
  problem demonstrated above.
- **Richer lexicon baseline**: extend `lexicon_baseline.py` with
  intensifiers ("very", "extremely" boost the score), degree modifiers, or
  a proper published lexicon (e.g. AFINN or a VADER lexicon file) for a
  stronger classical baseline.
- **Better ML features**: try word embeddings (e.g. the from-scratch
  Word2Vec in a companion project) as features instead of TF-IDF, which
  may generalize better to unseen vocabulary than bag-of-n-grams.
